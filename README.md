# GardiaRadar

GardiaRadarは、Bryton Gardia R300(R300L)の**自転車用後方レーダーデバイス**と連携し、接近する車両の情報をAndroidスマートフォンおよびWear OSスマートウォッチでリアルタイムに表示・通知するためのシステムです。

視覚的なインジケーターに加えて、振動と音による警告機能を備えています。

---

## 📖 開発の経緯

市販の自転車用レーダーは、対応サイコンやガーミンウォッチと連携して車両の接近を知らせてくれますが、実際に使ってみると**不満な点**がありました。

### ❌ 市販製品組み合わせの問題点

| 組み合わせ | 問題点 |
|------------|--------|
| **レーダー + サイコン** | 車両を検知している間、**過剰に通知が鳴り続ける**（後続車がいる間ずっとアラート） |
| **レーダー + ガーミンウォッチ** | 遠距離で車列表示は出るが、**警告音や振動がない** |

そしてどちらの組み合わせにも共通する問題：

**「後ろからの車が通り過ぎる直前」にアラートされても、もう遅い**

### ✅ 本当に欲しかったもの

- 車列を**検知したら「一度だけ」**知らせてほしい（警告を受けた後は、自分で後方への意識を向けるため）
- その後、ずっと鳴り続けるのは不要
- ガーミンウォッチのように「表示はあるのに警告がない」では意味がない
- バッテリー残量低下通知の閾値を自分で設定したい

既存製品には**「最初の一回だけ通知するモード」**が存在しませんでした。そこで、**自分の欲しい機能を実現するためにこのシステムを作りました**。

### 🎯 このシステムの目玉

**FIRST_ONLYモード** — 新しい車列を検知した**最初の1回のみ**通知。後続車が連続して通過しても過剰なアラートは発生しません。

## 🚀 主な機能

- **後方レーダー連携**: Bluetooth LE経由でレーダーデータ（車両の距離・速度・脅威度）を受信。
- **マルチデバイス表示**: スマホのレーダービューに加え、Wear OSでのリアルタイム車列表示に対応。
- **カスタマイズ可能なアラート**: 音・振動をそれぞれ個別にON/OFF可能。スマホ・ウォッチそれぞれで設定。
- **バッテリー監視**: レーダー、スマホ、ウォッチすべての電池残量を一括管理し、低下時に通知。
- **ライド・計測機能**: 接続ごとの経過時間（ライド時間）を計測し、ウォッチとスマホの両方で確認可能。
- **通信・走行ログ**: 接続セッションごとの通信統計やバッテリー消費データを詳細に自動記録。
- **省電力設計**: Wear OS向けの「省電力モード」や、バックグラウンドでの安定動作。

## 🏗 システムアーキテクチャ

システムは2つのモジュールで構成され、Google Wearable Data Layer APIを通じて密接に連携します。

### 1. スマホアプリ (`app`)
レーダーとの通信、データ解析、通知管理、およびデータのハブとして機能します。
- **RadarScanService**: バックグラウンドでデバイスをスキャン。Androidの制限を回避するスロットリング機能を搭載。
- **RadarRepository**: GATT通信の本体。パケットデコード、電池管理、セッション記録を担当。
- **RadarNotificationManager**: スマホ上での通知生成。
- **WearableDataHost**: 車両位置やデバイス状態をWear OSへリアルタイム同期。
- **BatterySessionRepository**: 通信履歴（ON/OFFセッション）を永続化し、期間や通信回数を管理。

### 2. Wear OSアプリ (`wear`)
ライダーがハンドルから手を離さずに状況を把握するための専用インターフェースです。
- **MainActivity**: 時刻、各デバイスの電池、および200m先までの車両位置をグラフィカルに表示。
- **RadarListenerService**: スマホからの各種信号を受け取り、フィードバックやデータの永続化を担当。
- **省電力モード**: 有効時は画面表示を停止し、警告通知のみに特化してスマートウォッチの電池消費を抑えます。

## 📱 スマホアプリの機能詳細

### メイン画面・設定
- **レーダービュー**: 自転車アイコンを頂点としたレーン表示。車両の脅威度に応じて色分け（赤=高速接近、白=通常）。
- **通知モード設定**: スマホ・ウォッチそれぞれに対し、以下の3モードを選択可能。
    - `OFF`: 通知なし。
    - `FIRST_ONLY`: 新しい車列を検知した「最初の一回」のみ通知。後続車が連続して通過する場合の過剰なアラートを抑えます。
    - `EVERY_TIME`: 車両を検知している間、毎秒通知。非常に高い警戒が必要な場合に使用します。
- **低電池しきい値**: レーダーの電池残量が指定値を下回った際に警告を出す設定。
- **音・振動設定**: スマホ・ウォッチそれぞれで、車両検知時のサウンドと振動を個別にON/OFF可能。

### 信頼性とログ
- **バックグラウンド動作**: 端末起動時の自動開始（BootCompleted）や、バッテリー最適化設定のチェック機能を備えています。
- **通信履歴（セッションログ）**: 
    - レーダー接続中（ON）と非接続中（OFF）のすべての期間を記録。
    - 各ログには `開始時刻 〜 終了時刻 (所要時間)` および `通信回数（内訳含む）`、`バッテリー消費` が記録されます。
    - 履歴画面から個別のセッションを削除することも可能です。

## ⌚ Wear OSアプリの機能詳細

### 走行中画面
- **車列インジケーター**: 50m/100m/150m/200mのメモリ線。最大4台までの車両をドットで表示。
- **ライド時間（接続経過時間）**: 
    - レーダー接続時に自動で計測を開始（⏱️アイコン）。
    - 切断時はタイマーが停止し、最終時間が維持されます（🏁アイコン）。
    - アプリを完全に終了しても、最新のライド記録は `SharedPreferences` により維持され、次回のライド開始時にリセットされます。
- **接続フィードバック**:
    - **接続時・切断時共通**: 短い振動2回 + ビープ音1回（音・振動は設定で個別にON/OFF可能）。
    - 切断時は**60秒後に自動でアプリを終了**しウォッチフェイスに戻ります。

### 安定性とインテリジェンス
- **グリッチ・フィルター**: Bluetoothの瞬断による意図しないリセットを防ぐため、**5分以内の再接続であれば同じライドとみなして継続**します。
- **オートフィニッシュ**: 切断後60秒間は、結果を確認するために画面を維持します。その後、自動でウォッチフェイスに戻ります。

### 警告（アラート）仕様
スマホが危険を察知すると、Message API経由で強制的にアラートを発火させます。
- **振動**: 最大振幅でのウェーブフォーム振動（設定でOFF可能）。
- **音**: アラーム音（`TYPE_ALARM`）を最大音量で1回再生（設定でOFF可能）。
- **自動停止**: 4秒経過で自動停止。

### 省電力モードの動作詳細

省電力モードを有効にすると、ウォッチの画面表示を停止し、**警告通知（振動・音）のみ**で動作します。ただし、音・振動設定でOFFにしている場合はその限りではありません。

#### 通常モード時の動作
- ✅ 車両の接近をリアルタイムで画面に表示
- ✅ 警告時にアプリが自動的に前面に表示
- ✅ 振動と音による警告

#### 省電力モード時の動作
- ❌ 車両の接近を画面に表示しない（アプリ起動なし）
- ❌ 接続/切断時に画面が自動で点灯しない
- ✅ 振動と音による警告

## 🔌 通信プロトコル

### Bluetooth LE (Radar ↔ Phone)
- **Service**: Standard Battery Service & Custom Radar Service
- **Radar Data Characteristic**: `f3641401-00b0-4240-ba50-05ca45bf8abc` (Notify)
- **Battery Characteristic**: `00002a19-0000-1000-8000-00805f9b34fb` (Read/Notify)
- **データパケット**（20バイト、2バンク構成）:
    - 詳細なデコード仕様は [docs/radar_packet_decoding.md](docs/radar_packet_decoding.md) を参照
    - `0x30` バンク: 全4脅威のレベル・距離・速度をビットパックで格納
    - `0x31` バンク: 拡張用（観測上は実質空）

### Wearable API (Phone ↔ Wear)
- **Data Layer (`/radar-targets`, etc.)**: 状態の同期用。低遅延で車両位置を更新。
- **Message API (`/radar-alert`)**: 即時性が求められる警告信号用。

### 🧠 スマート通知機能（通知抑制機能）

本システムには、頻繁な通知を軽減するためのクールダウン機能が実装されています。

- **通知抑制タイム (Clear Suppression Time)**:
  車両がいなくなってから指定秒数（設定で0〜60秒に変更可能）の間に再度車両を検知しても、新しい通知（音・振動）を発生させません。
- **動作の仕組み**:
  最初の車列が去った直後に次の車が来た場合、それを「同じイベントの継続」として扱い、過剰な通知を抑止します。
- **視覚的なフィードバック**:
  スマホのメイン画面には `CDTimer` として抑制期間の残り秒数が表示されます。なお、通知が抑制されている間も、画面上のドット（車両位置）はリアルタイムに更新されます。

## 🛠 開発とビルド

### 環境
- Kotlin / Jetpack Compose / Wear Compose
- Koin (Dependency Injection)
- Coroutines & Flow
- Room (Battery History)

### ビルドコマンド
```bash
# 全モジュールのビルド
./gradlew assembleDebug

# Phoneアプリのみ
./gradlew :app:assembleDebug

# Wear OSアプリのみ
./gradlew :wear:assembleDebug
```

### Wear OSアプリのインストール

ビルド後、以下の手順でウォッチにインストールします。

#### 1. APKの場所を確認
```
wear/build/outputs/apk/debug/wear-debug.apk
```

#### 2. Wear OSデバイスで開発者モードを有効化
- ウォッチの **設定 > システム > バージョン情報** を開く。
- 「ビルド番号」を7回タップして開発者モードにする。
- **設定 > 開発者オプション** で「ADBデバッグ」をONにする。

#### 3. PCと接続
**WiFi経由（推奨）:**
- ウォッチと同じWiFiに接続。
- **設定 > 開発者オプション > ワイヤレス デバッグ** をタップして開き、表示されている「IP アドレスとポート」を確認。
  - ※ Wear OS 3以降ではポート番号が `5555` 以外（例: `38475` など）になる場合があります。
```bash
adb connect [表示されたIPアドレス]:[ポート番号]
```

**USB経由:**
```bash
adb devices
```

#### 4. インストール実行
```bash
adb install -r wear/build/outputs/apk/debug/wear-debug.apk
```
